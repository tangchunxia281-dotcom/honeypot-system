# 风险目标标注功能 · 实现计划

## Context（背景）

用户要求为既有蜜罐系统新增「风险目标标注」能力。当前系统通过 `db/event_logs.py` 的统一事件模型（`event_log` 表）记录来自 SSH/Web/MySQL/Redis/FTP/Telnet 的攻击事件，并在管理端大屏做统计展示，但**缺少**「将某个攻击源（IP）标记为风险目标并进行标注（风险等级、处置状态、标签、备注）」的能力。

本功能目标：在**不改动现有事件写入链路**（`log_event` 签名与语义保持不变）的前提下，新增一张独立的风险目标表、一套读写/自动识别函数、一组管理端 API，以及大屏上的「风险目标标注」面板，用于查看、自动识别并对风险目标做人工标注。

## 设计要点

- **风险目标 = 攻击源 IP**：每条风险目标唯一对应一个 `src_ip`（`target_type='ip'`；表结构预留 `session` 扩展，但不实现）。
- **两级能力**：
  1. **自动识别（derive）**：从 `event_log` 聚合最近 N 小时内的攻击事件，命中「事件数 ≥ 阈值 且 最高严重度 ≥ 阈值」的 IP 自动进入风险目标（`source='auto'`）。
  2. **人工标注（annotate）**：管理端对风险目标增/改/删，设置 风险等级、处置状态、标签、备注（`source='manual'`）。
- **风险等级**对齐现有 `severity` 口径：`low / medium / high / critical`。
- **处置状态**：`watching`（观察中）/ `banned`（已封禁）/ `handled`（已处置）。
- **归档策略**：`risk_target` 属运营态标注数据，**不纳入** `db/archive.py` 的冷归档，故无需改归档逻辑。

## 新增 / 修改文件清单

### 1. 新增 `db/risk_targets.py`（核心数据访问层）
- 复用 `db/connection.py` 的 `get_connection()`、`USE_MYSQL`、`_truncate_text`、`_redact_sensitive_text`。
- `_ensure_risk_target_table(conn)`：仿照 `db/event_logs.py::_ensure_event_log_table`，按 `USE_MYSQL` 分支 `CREATE TABLE IF NOT EXISTS`，并对旧库执行 `ALTER TABLE ADD COLUMN` 迁移缺失列。
- 表结构（字段）：
  - `id` 自增主键
  - `target_type` VARCHAR(16) DEFAULT 'ip'
  - `target_value` VARCHAR(64) NOT NULL UNIQUE（存 IP）
  - `risk_level` VARCHAR(16) DEFAULT 'medium'
  - `status` VARCHAR(16) DEFAULT 'watching'
  - `tags` TEXT（JSON 数组字符串）
  - `note` TEXT（人工备注）
  - `source` VARCHAR(16) DEFAULT 'auto'
  - `first_seen` / `last_seen` DATETIME
  - `event_count` INT DEFAULT 0
  - `created_at` / `updated_at` DATETIME
  - 索引：`target_value` 唯一、`risk_level`、`status`
- 函数（均返回普通 dict，供 API 层 `_sanitize_records` 清洗）：
  - `derive_risk_targets(hours=None) -> int`：聚合 `event_log`（仅 `source in (web,ssh,mysql,redis,ftp,telnet)`、排除 `_HIDDEN_EVENT_TYPES`、`timestamp >= cutoff`）；对每个 IP 统计 `event_count` 与最高严重度；命中阈值则 `INSERT ... ON DUPLICATE KEY UPDATE` / `INSERT ... ON CONFLICT(target_value) DO UPDATE` 更新统计字段；**仅更新 `source='auto'` 行的标注字段，人工行只刷新统计（first_seen/last_seen/event_count），不覆盖人工标注**。
  - `list_risk_targets(...)`：支持 `risk_level`/`status`/`keyword`/分页筛选。
  - `get_risk_target(target_id=None, target_value=None)`。
  - `upsert_risk_target(...)`（人工新增/标注）。
  - `update_risk_target(target_id, **fields)`（限白名单字段）。
  - `delete_risk_target(target_id)`。

### 5. 修改 `dashboard/server.py`
- 顶部导入新函数。
- 新增 4 个端点（全部 `@enhanced_login_required`，写操作用 `@csrf_protect_api`，写法仿 `api_suspicious_requests`）：
  - `GET /api/risk_targets`：`?risk_level=&status=&q=&limit=&offset=` → 列表；复用 `_format_ip_location` 给每条加 `location`。
  - `POST /api/risk_targets/derive`：`derive=1` 时先 `derive_risk_targets()`，返回生成数量；`enabled=false` 时返回提示。
  - `POST /api/risk_targets`：人工新增（body 含 `target_value`、`risk_level`、`status`、`tags`、`note`）。
  - `POST /api/risk_targets/<int:tid>`：更新标注（白名单字段）。
  - `POST /api/risk_targets/<int:tid>/delete`：删除。
- 返回值统一 `{'code': 0, 'msg': 'success', 'data': ...}`。

### 6. 修改 `database/schema.sql`
- 追加 `risk_target` 建表语句（MySQL 口径，与 `db/risk_targets.py` 一致）。

### 7. 修改前端
- `dashboard/templates/dashboard.html`：新增「风险目标标注」面板（复用 `.panel`/`.panel-title`），内含风险目标列表容器 + 一个简单的标注 modal（字段：风险等级 select、状态 select、标签 text、备注 textarea、保存/删除按钮）；用 `{{ csrf_token() }}` 渲染隐藏 token 供 JS 读取。
- `dashboard/static/js/dashboard.js`：新增 `updateRiskTargets(data)` 渲染函数（列表 + 每行「标注/删除」按钮，`risk_level` 用 badge 色块、`status` 用中文映射），并处理 modal 的保存/删除 fetch（POST 带 `X-CSRF-Token` 头）。
- `dashboard/static/js/dashboard_data_flow.js`：在刷新流程中新增对 `/api/risk_targets` 的 fetch（复用 `fetchJsonWithTimeout`），成功后调用 `updateRiskTargets`。
