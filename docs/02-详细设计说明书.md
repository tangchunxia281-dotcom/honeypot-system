## 1. 主控模块 main.py

### 1.1 职责与数据结构

统一管理全部子服务进程。核心数据结构：

```python
SERVICES: List[Dict]  # 每项: name/script/args?/host/port/description/color/short
processes: Dict[str, subprocess.Popen]        # 服务名 -> 进程句柄
service_status: defaultdict(dict)             # 服务名 -> {restarts, last_exit, ...}
shutdown_flag: bool                            # 全局停止标志
```

- 多协议扩展服务按 `DB_HONEYPOT_ENABLED` / `FILE_HONEYPOT_ENABLED` / `REMOTE_HONEYPOT_ENABLED` 条件追加；
- team_center / ai_gateway 先读 JSON 配置取 host/port（`_load_service_endpoint`，失败返回 `(None, None)`），再条件注册；
- 凭证等待参数：`SUMMARY_CRED_WAIT`（默认 2s，`inf` 收敛到 `SUMMARY_CRED_WAIT_MAX=15s`，防启动卡死）。

### 1.2 核心算法

1. **端口预检**：`check_port` 用 `SO_EXCLUSIVEADDRUSE`(Win)/`SO_REUSEADDR` 尝试 bind，全部可用才继续，任一占用即中止。
2. **流式日志汇聚**：每子进程两个守护线程分别读 stdout/stderr 行，按服务着色 + 前缀输出；`CRED::user::pass` 行被捕获进凭证汇总。防止管道缓冲写满导致子进程阻塞。
3. **崩溃自动重启**：监控线程周期检查 `poll()`，异常退出且未达 `MAX_RESTART_ATTEMPTS`（默认 5）则 `RESTART_DELAY`（默认 3s）后重启；达上限标记失败不再拉起。
4. **优雅退出**：SIGINT/SIGTERM 置 `shutdown_flag`，按依赖顺序终止子进程并等待。

### 1.3 异常处理

- 配置读取失败：回退默认值并打印提示（如 team_center JSON 缺失打印 `!` 提示跳过注册）。
- 子进程启动失败：记入 `service_status`，不中断其他服务。
- Windows/Unix 信号差异：`SIGTERM` 存在性判断（`hasattr(signal,'SIGTERM')`）。

### 1.4 单元测试设计

| 用例 | 方法 |
| ---- | ---- |
| 端口占用检测 | 先占用端口起 socket，断言 `check_port` 返回 False |
| 配置解析边界 | `SUMMARY_CRED_WAIT=inf/-1/abc/2` 分别断言收敛结果 |
| 服务注册开关 | 设置/清除 `*_ENABLED`，断言 SERVICES 长度与项 |
| 重启上限 | mock Popen 连续退出，断言重启次数 ≤ 上限且状态标记 |

## 2. 配置模块 app_config.py / env_utils.py

### 2.1 设计

- 读取优先级：**环境变量 > honeypot.ini > 代码默认**；`_ENV_CONFIG_MAP` 将环境变量名映射到 ini 的 `(section, key)`，一份映射兼容两种来源。
- `env_bool/env_int/env_float/env_str` 四族函数做类型转换与范围钳制（`env_int(name, default, min, max)`）。
- `SECRET_KEY` 优先从 `.secret_key` 文件读取/生成，避免硬编码。
- `Config/DevelopmentConfig/ProductionConfig/config` 保留 Flask `from_object` 兼容入口。

### 2.2 异常处理

- ini 不存在/解析失败 → `CONFIG_LOADED=False`，全部走默认值；
- 数值转换异常 → 回退 default；布尔只认 `{1,true,yes,on,y}` / `{0,false,no,off,n}`。

### 2.3 单元测试设计

- 环境变量覆盖 ini、ini 覆盖默认的三层优先级用例；
- `env_int` 越界钳制、非数字回退；
- 未知布尔串回退默认。

## 3. 治理层 utils/protocol_guard.py

### 3.1 数据结构

```python
class ConnectionGuard:
    _active_total: int                     # 全局活跃连接
    _active_per_ip: Dict[str, int]         # 单 IP 活跃
    _fails: Dict[str, Deque[float]]        # 认证失败时间戳
    _ban_until: Dict[str, float]           # 封禁到期
    _ban_level: Dict[str, int]             # 封禁等级(指数退避)
    _preauth: Dict[str, Deque[float]]      # 预认证连接时间戳(扫描检测)
    _scan_cooldown: Dict[str, float]       # 扫描告警冷却
    _workers: threading.Semaphore          # worker 并发信号量
```

`ProtocolReporter(source, logger)`：持有 `_recent: Dict[dedup_key, last_ts]` 做 2.5s 去重。

### 3.2 核心算法

- **爆破封禁**：`record_auth_failure(ip)` 入队当前时间戳并滑窗清理；窗口内失败数 ≥ `fail_threshold`(12) 时 `ban_seconds = min(base * 2^level, max)`（600→7200），level+1；`admit(ip)` 检查 `ban_until`。
- **扫描检测**：`record_preauth_connection(ip)` 滑窗计数 ≥ `scan_threshold`(18) 且过冷却则返回命中详情 `{'window_seconds','count'}`。
- **评分分级**：`severity_from_score`：<40 low / 40–59 medium / 60–79 high / ≥80 critical（阈值取自 `utils.alerting` 配置）。
- **会话标识**：`make_protocol_session_id` = `{protocol}-{md5(protocol:ip:hour_window)[:16]}`。

### 3.3 接口细节

```python
guard.admit(ip) -> (bool, reason)              # reason in ('ok','banned','too_many_total','too_many_per_ip')
guard.acquire_worker(timeout) -> bool
guard.record_auth_failure(ip) -> Optional[ban_info]
guard.record_preauth_connection(ip) -> Optional[scan_info]
guard.release(ip) / guard.release_worker()
reporter.event(event_type, ip, score=0, payload='', tags=None, session_id='', extra=None) -> Optional[int]
```

### 3.4 异常处理

- 全部状态操作加锁；队列清理用滑窗而非定时器，无线程泄漏；
- `reporter.event` 内部调用 `log_event` 失败仅记 debug，不抛给协议处理器；
- 封禁/扫描状态全内存态，进程重启自动清零（蜜罐场景可接受）。

### 3.5 单元测试设计

| 用例 | 断言 |
| ---- | ---- |
| 12 次失败触发封禁 | 第 12 次 `record_auth_failure` 返回 ban_info，`admit` 拒绝 |
| 指数退避 | 连续触发封禁，时长按 2 倍增长且 ≤ max |
| 扫描窗口 | 10s 内 17 次不命中、18 次命中；冷却期内不重复上报 |
| 去重 | 2.5s 内同 type+ip 事件只写一次 |
| 分级映射 | 0/40/60/80 边界值映射正确 |

## 4. 数据层 db/

### 4.1 connection.py

- **双后端**：`USE_MYSQL = config.DB_TYPE=='mysql'`；SQLite 路径默认 `database/event_logs.db`。
- **SQLite 写重试**：`_sqlite_run_with_retry(conn, action)`，捕获 `sqlite3.OperationalError('database is locked')`，按 `SQLITE_BUSY_RETRY`(3) 次、`SQLITE_BUSY_BACKOFF`(0.05s 起指数) 重试。
- **脱敏**：`_redact_sensitive_text` 对 `secret/token/authorization/api_key/令牌/密钥` 等键的 kv/JSON 形态替换为 `<redacted:sha256[:10]>`；`_truncate_text` 按字符限长。

### 4.2 event_logs.py（统一事件日志）

**写入 `log_event`**：归一化 source（白名单外归 `system`）/ severity（含中文映射 严重/高危/警告/提示）→ 截断（event_type 64、ip 64、payload 2048、extra 4096，可配）→ tags JSON（≤20 个、单项 ≤24 字符）→ 脱敏 → INSERT；北京时间 `_now_text()`（ZoneInfo Asia/Shanghai），避免 SQLite `CURRENT_TIMESTAMP` 的 UTC 偏差。成功后清统计缓存。

**查询 `get_event_logs`**：limit ≤500、offset ≤50000、hours ≤720 钳制；多维过滤（source/severity/event_type/keyword/hours）；隐藏类型 `_HIDDEN_EVENT_TYPES=('ssh_cmd_audit','ssh_cmd_suspicious','web','web_activity_note')` 默认不进聚合识别（防噪声）；超窗数据合并冷归档（`fetch_archive_*`）后按 `(timestamp,id)` 倒序归并。

**统计 `get_event_stats`**：按小时窗聚合（总量/分级/来源分布/类型 Top/时间曲线），进程内缓存 TTL 3s（`_EVENT_STATS_CACHE_MAX_KEYS=16`，最旧淘汰）。

**异常处理**：写入失败返回 `None` 并 debug 日志（蜜罐不因落库失败崩溃）；表自初始化 `_ensure_event_table_ready` 双检锁，MySQL 侧做 `raw_request_id` 列/索引的幂等迁移。

### 4.3 http_requests.py（Web 请求捕获与评分）

**规则特征库**（正则/标记元组）：
- SQLi：标记串（`' or `、`union select`、`sleep(` 等）+ 注释符组合正则 + 弱特征变体（不闭合引号 `') OR ('1'='1`）；
- XSS：`<script`、`javascript:`、`onerror=`、`document.cookie` 等；
- JNDI：`${jndi:(ldap|rmi|dns|...)://`；表达式注入：`${...}` / `#{...}`；
- 扫描器指纹：sqlmap/nmap/nessus/awvs/masscan UA 标记；扫描路径：`/hnap1`、`/sdk`、`/boaform`、`/cgi-bin`、`/actuator` 等；
- WebShell：`/shell.php` 等路径 + `cmd=`/`antsword=` 参数键；
- 命令执行：`cmd.exe /c`、`/bin/sh`、`powershell -enc`、`system(`、`base64_decode(` 等。

**评分算法**：命中特征按权重累加威胁分（0–100 钳制），叠加可选 AI 加权分（`ai_points` 0–25）；`severity_from_score` 分级；≥40 写 event_log 并告警。会话 ID 按 `SESSION_ID_WINDOW_SECONDS`(3600s) 滑窗 md5 生成。

**异常处理**：解码异常（URL/HTML）容错；AI 调用任何异常静默降级为无 AI 分；演示数据仅在 `ALLOW_DASHBOARD_MOCK_DATA` 且无真实数据时启用。

### 4.4 risk_targets.py（风险目标标注）

- **自动识别 `derive_risk_targets(hours)`**：聚合近 N 小时（默认 24，上限 720）event_log 中六类蜜罐来源、排除隐藏类型，按 src_ip 分组；门槛 `RISK_TARGET_MIN_EVENTS`(2) 且最高严重度 ≥ `RISK_TARGET_MIN_SEVERITY`(medium)；存在则更新统计，**source=manual 的记录只刷统计（first_seen/last_seen/event_count），不覆盖 risk_level/status/tags/note**；不存在则以 `watching/auto` 插入。
- **人工标注 `upsert/update/delete`**：target_value 唯一；tags ≤20 项；note ≤2000 字符；level/status 归一化（非法值回退 medium/watching）。
- **异常处理**：所有写返回 `{'ok':bool,'msg'/'id'}`，异常仅 debug 日志；表自初始化双检锁。

### 4.5 archive.py / geo.py / demo_data.py

- 归档：按时间阈值把 `raw_request/session_track/event_log` 搬迁至归档库（MySQL 下为 `honeypot_archive` 库；`geo_ip`、`risk_target` 不归档），查询侧透明合并；
- geo：GeoLite2 查询 + `geo_ip` 表缓存，失败返回 unknown；
- demo_data：构造模拟可疑请求/会话分析，默认禁用。

### 4.6 数据层单元测试设计

- log_event 归一化（未知 source→system、中文 severity 映射、超限截断、脱敏生效）；
- SQLite 锁重试（并发写注入 locked 错误）；
- get_event_logs 过滤与归档合并排序；
- risk_targets 自动识别门槛、人工标注不被覆盖、CRUD 边界；
- 评分器：构造 SQLi/XSS/JNDI 样本断言分数区间与事件落库。

## 5. 蜜罐接入层

### 5.1 数据库蜜罐 db_honeypot

**结构**：单进程双线程监听（`_serve` 通用 TCP 接入循环：accept → 守护线程 `_handle_client` → 扫描检测 → worker 信号量 → admit → `handler.handle`）。MySQL/Redis 各持独立 guard/reporter。

- **mysql_handler.MySQLHoneypot**：实现 MySQL 握手包、认证响应、COM_QUERY 仿真；`DECOY_ACCOUNTS` 诱饵凭证；登录成功/失败、查询、爆破事件按特征评分上报（source=mysql）。
- **redis_handler.RedisHoneypot**：RESP 协议解析，仿真 PING/AUTH/INFO/GET/SET/CONFIG 等命令子集；危险命令（FLUSHALL/CONFIG/KEYS *）高分上报（source=redis）。
- 启动时 `EMIT_CREDENTIAL_LINES` 控制打印 `CRED::` 凭证行供 main 汇总。

**异常处理**：端口绑定失败置 `_stop_event` 全进程退出；单连接异常仅 debug 并释放资源；SIGINT/SIGTERM 优雅停止。

**测试设计**：socket 客户端模拟握手/认证/查询，断言事件入库（event_type、source、score）；并发 30 连接断言限流生效。

### 5.2 文件共享蜜罐 file_honeypot（FTP）

- 每连接独立 `FTPHoneypot` 实例（PASV 套接字/登录态/工作目录为连接级状态）；
- 仿真 USER/PASS/PWD/CWD/LIST/RETR/STOR/PASV/TYPE 等命令；伪文件系统树；匿名登录 `(任意邮箱)` 也作诱饵；
- 登录爆破、敏感目录遍历、上传行为评分上报（source=ftp，含 `ftp_port_scan`）。
- 测试：ftplib 客户端走匿名/错误凭证/遍历/PASV 列表用例，断言响应码仿真正确且事件入库。

### 5.3 远程管理蜜罐 remote_honeypot（Telnet）

- 每连接独立 `TelnetHoneypot`（IAC 协商缓冲/登录状态机/busybox 风格 shell）；
- 典型 IoT 凭证诱饵（`DECOY_ACCOUNTS`），命令子集 + 下载行为（wget/curl tftp）高分上报（source=telnet）。
- 测试：raw socket 走 IAC 协商、错误/正确凭证、执行命令序列，断言事件与响应仿真。

### 5.4 SSH 蜜罐 ssh_honeypot

- Paramiko ServerInterface 仿真：密码认证（限次 `SSH_MAX_AUTH_TRIES`）、`session.py` 会话状态机、`commands.py` 命令库（18 万行级）、`vfs.py` 虚拟文件系统；
- 运行时目录 `ssh_honeypot/state/` 自动创建（密钥生成补丁，防全新部署崩溃）；
- 命令审计事件（`ssh_cmd_audit`/`ssh_cmd_suspicious` 属隐藏类型，不入聚合噪声）、登录爆破走治理层封禁。
- 测试：paramiko 客户端错误/正确凭证、执行 ls/cat/wget 等，断言会话事件与命令审计入库。

### 5.5 Web 蜜罐 web_honeypot

- Flask 多文件路由：`routes_public`（企业站公开页/联系/订阅/搜索/新闻/robots/sitemap）、`routes_traps`（`/.env`、`/.git/config`、`/backup*`、`/admin_v2/*`、伪登录 API、上传目录、`/backup.zip` 等诱饵下载）、`admin_views`（伪后台登录/仪表盘/备份/上传）、`admin_api`（伪 REST：me/access_logs/settings/content/users/submit_change/audit）；
- 全部请求经 `db/http_requests` 捕获评分；响应经 `utils/http_fingerprint` 指纹伪装（Server 头等）；
- 登录表单、搜索、联系表单为攻击面收集点；上传做安全存放（不执行）。
- 测试：requests 走公开页 200、陷阱路径诱捕响应、伪后台登录流程、SQLi 参数触发高分事件。

## 6. 应用层 dashboard/

### 6.1 认证与安全

- **登录** `/super/login`：账号来自配置（`ADMIN_USER`/`ADMIN_PASS`）；限速：60s 窗口 8 次、封禁 300s（均可配）；审计 deque（上限 200，展示近 30）。
- **会话**：`DASHSESSID` Cookie，HttpOnly + SameSite=Lax +（可配）Secure；有效期默认 1440 分钟。
- **CSRF**：登录后 session 内 `csrf_token`，写接口校验 `X-CSRF-Token` 头 + Referer/Origin 同源（`_build_dashboard_allowed_origins` 自动推导 + `DASHBOARD_ALLOWED_ORIGINS` 可配）。
- **加固**：`enhanced_login_required` 装饰器、CSP 严格同源、X-Frame-Options=DENY、nosniff、Referrer-Policy 平衡值、ProxyFix 仅在显式信任代理时启用（`DASHBOARD_TRUSTED_PROXY_IPS` CIDR 白名单）。
- **资产版本**：`_build_asset_version` 取静态文件 mtime 最大值做缓存破击。

### 6.2 数据接口实现要点

- 大屏三档窗口：24h/7d/30d 各配 geo/suspicious/session 限量（如 24h：60/50/50），防大窗慢查；
- `/api/realtime` 增量事件流（按 id 游标）；
- `/api/suspicious_requests`、`/api/session_analysis` 走 `db/http_requests` 行为分析（非规则匹配）；
- `/api/server_info`、`/api/system_status` 来自 `dashboard/system_info.py`（psutil 指标，容错降级）。

### 6.3 风险目标接口

- GET 列表支持 type/level/status/keyword/limit/offset；
- POST `/derive` 触发自动识别；POST 创建、`/<id>` 更新、`/<id>/delete` 删除，全部 CSRF 校验；
- 响应统一 `{code,message,data}`。

### 6.4 AI 工作区接口

- `_ai_safe_endpoint` 装饰器：AI 存储不可用时返回明确错误而非 500；
- 编号参数统一 24 位十六进制正则校验（无效 400）；
- 导出接口返回附件（Content-Disposition）。

### 6.5 异常处理

- API 层 try/except → `{code:1,message:...}` 或对应 HTTP 码；参数钳制在 db 层与路由层双重进行；
- 登录失败/CSRF 失败不泄露具体原因（统一提示）。

### 6.6 单元测试设计

| 用例 | 断言 |
| ---- | ---- |
| 错误密码登录 | 401 + 审计记录 + 限速计数 |
| 缺 CSRF 写操作 | 403 |
| 未登录访问 /dashboard | 302 跳登录 |
| 登录限速 | 第 9 次尝试被封禁 |
| risk_targets 全流程 | derive/create/update/delete 数据正确且 manual 不被覆盖 |
| AI 状态降级 | AI 关闭时 status 接口返回明确 enabled=false |
| 窗口参数 | hours=1/25/720 钳制到合法档 |

## 7. 智能层 utils/ai_*

### 7.1 ai_settings.py

`load_settings()` 返回 dict：provider 三分支强校验——
- `local`：base_url 必须 http(s) + 回环 host + 无凭证/查询/路径，model ≤160 字符；
- `gateway`：gateway_url 回环或内网（10/8、172.16/12、192.168/16、fc00::/7），非回环须 https 或 `allow_insecure_lan`；token 32–256 位 `[A-Za-z0-9_-]`；
- `deepseek`：base 必须 https、api_key 匹配 `sk-[A-Za-z0-9]{20,}`；timeout 默认 30。

任何校验失败 `configured=False` + `configuration_error`，上游据此禁用 AI。运行库路径 `HONEYPOT_AI_DB`/ini `runtime_db`（默认 `database/ai_runtime.db`）。

### 7.2 local_ai.py

- 统一推理入口：按 provider 分发 Ollama `/api/generate` / 网关 jobs / DeepSeek `/chat/completions`；
- 并发信号量（`concurrency` ≤4）、会话内调用上限、最小间隔、熔断（失败计数开窗）；
- `status()` 输出 enabled/provider/model/configured/队列与熔断指标，供 `/api/ai/status`。

### 7.3 ai_analyst / ai_analyst_store

- 后台 worker：`analyst_cursors` 记录各源消费位置 → 批量取新事件 → `evidence_selection` 选样（分析批 24、样本 6 可配）→ 任务入 `analyst_tasks`（fingerprint 唯一去重）→ 推理 → `analyst_report_items`/`analyst_reviews`/`analyst_attempts`；
- 归档：`archived_tasks`（保留 `analyst_retention_days` 默认 30 天）；
- 模式切换（periodic/manual）、flush 间隔（默认 60s）均可配。

### 7.4 investigations.py

- 攻击调查案例：`investigations` + `investigation_reports` + `investigation_audit`；
- **修订冲突控制**：更新携带 revision，`Conflict` 异常 → 409，防并发覆盖；
- 导出为 JSON 附件。

### 7.5 ai_detection / ai_interaction

- detection：抽样队列（`detection_queue_max` 32、每 IP 小时 20、正常样本每 10 抽 1）、延迟执行、结果落 `ai_detections`；
- interaction：Web 蜜罐交互问答会话（TTL 1800s、≤128 会话、≤100 步、每 IP 小时 40），步骤落 `ai_interactions`/`interaction_sessions`。

### 7.6 ai_client.py（远程检测客户端）

- **熔断**：连续失败 ≥ `AI_XSS_FAILURE_THRESHOLD`(3) → 退避 `AI_XSS_BACKOFF_SECONDS`(30s)，期间 `backoff_skips` 短路；
- **脱敏**：password/passwd/pwd/token/secret/api_key/authorization 的 kv 与 JSON 形态替换；
- **契约校验**：响应须含合法 attack_type/is_attack/attack_prob/ai_points(0–25) 等，非法计 `invalid_responses` 并视为失败；
- **指标**：attempts/successes/failures/timeouts/延迟均值/模型信息缓存（TTL 300s），供大屏 AI 状态展示；
- 超时默认 1s（0.1–10 可配），绝不阻塞蜜罐主流程。

### 7.7 智能层单元测试设计

- settings：local/gateway/deepseek 合法与非法配置矩阵（http 公网、弱 token、非 sk- key 均判 unconfigured）；
- ai_client：未启用短路、服务不可达熔断与恢复、v2 契约解析、脱敏、非法响应五用例（已实测通过）；
- analyst：fingerprint 去重、游标推进、归档保留期；
- investigations：revision 冲突 409。

## 8. 可选子服务

### 8.1 team_center（团队数据中心）

- **认证**：`/login`（JSON，CSRF 头校验，每 IP 10 次/5 分钟限速）→ Session（`honeypot_center` Cookie，SameSite=Strict，30 分钟）；`guards` 提供 `login`/`role('admin','analyst')` 装饰器，非 GET 强制 `X-CSRF-Token`（hmac.compare_digest）。
- **传感器**：admin 签发/吊销；节点以 Bearer token（SHA-256 散列存储比对）调 `/api/ingest`（白名单字段 batch_id/records/health/metrics）与 `/api/heartbeat`（health 字段白名单 + ≤1000 字节）。
- **作业 JobStore**：`center_jobs`（owner+request_id 唯一幂等）/ steps / calls / feedback（revision 冲突 → 409）；
- **安全**：body ≤256KB、JSON 必须对象、统一错误（ValueError→400、PermissionError→403、sqlite3.Error→503）、安全响应头、审计表记录登录/签发/导出等。

### 8.2 ai_gateway（AI 推理网关）

- **持久化队列**：SQLite WAL `jobs` 表（client+request_id 唯一幂等；状态 queued/running/completed/fallback/cancelled）+ `gateway_state`（失败计数/熔断 blocked_until）；
- **调度**：容量 1–2；优先级 `TASKS` 映射（probe/ssh_reply/web_reply=3 … log_report=0）+ 等待时长老化加分；同客户端串行（NOT EXISTS running）；lease 机制防 worker 中断后脏写（75s 租约）；
- **配额**：全局队列 ≤64、每客户端待处理 ≤4、每分钟 ≤30（均可配）；
- **入参强校验**：request_id 24 位 hex、messages 1–12 条且仅 system/user/assistant、schema ≤6KB 禁 `$ref`、options 白名单（timeout 5–30/num_predict 64–1024/num_ctx 512–8192/think bool）、payload ≤24KB；
- **熔断**：模型连续失败 3 次 → 全局阻塞 30s，期间仅 probe 任务可领；
- **清理**：queued 超 120s、running 超 75s 置 fallback；完成态保留 1 小时。

### 8.3 子服务单元测试设计

- gateway：重复 request_id 幂等、超配额 429/Overflow 路径、优先级领取顺序、熔断后仅 probe 可领、lease 失配拒绝 finish；
- team_center：错误凭证 401、CSRF 403、role 拒绝 403、ingest 字段白名单 400、feedback 冲突 409。

## 9. 通用异常处理与日志规范

| 层级 | 策略 |
| ---- | ---- |
| 蜜罐接入 | 单连接异常不扩散；落库/告警失败仅 debug；绝不因治理逻辑中断协议仿真 |
| 数据层 | 写失败返回 None/{'ok':False}；查询异常回退空集；SQLite 锁重试 |
| Dashboard | API 统一 {code,message,data}；参数双重钳制；认证类错误模糊化 |
| AI | 一切外部调用带超时 + 熔断 + 降级；非法响应按失败计 |
| 日志 | `utils/logger.setup_logger` 统一滚动文件（LOG_MAX_BYTES/BACKUP_COUNT 可配）；主控 console_output=False 防重复 |
