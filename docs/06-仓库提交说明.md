# 仓库提交说明（上传清单与 Git 流程）

> 适用对象：需要把本项目提交到 GitHub / Gitee 的团队成员。
> 目标：代码可读、配置安全、评审可复现，仓库中不出现任何真实密钥与运行数据。

---

## 1. 上传范围

### 1.1 必须上传（代码与文档）

| 类别 | 文件 / 目录 | 说明 |
| --- | --- | --- |
| 程序入口与配置 | `main.py`、`app_config.py`、`env_utils.py` | 主控与统一配置读取 |
| 蜜罐服务 | `ssh_honeypot/`、`web_honeypot/`、`db_honeypot/`、`file_honeypot/`、`remote_honeypot/` | 六类协议仿真代码 |
| 数据层 | `db/`、`database/schema.sql`、`database/mysql_archive.sql` | 存储访问与建表脚本 |
| 公共工具 | `utils/` | 治理层、日志、告警、地理定位、AI 封装 |
| 管理端 | `dashboard/`（含 `templates/`、`static/`） | 态势大屏与 AI 工作区 |
| 可选子服务 | `team_center/`、`ai_gateway/` | 团队数据中心、AI 推理网关 |
| 评测 | `evaluation/`、`scripts/evaluate.py` | 评测样本集与评测脚本 |
| 脚本 | `scripts/`（不含 `honeypot.env`） | 启动、部署、演示、验收脚本 |
| 文档 | `README.md`、`API.md`、`AI_SerVice.md`、`docs/`（含截图与测试记录） | 设计与测试证据 |
| 配置模板 | `honeypot.ini.example`、`ai.local.ini.example`、`.env.example` | **只提交模板，不提交真实配置** |
| 依赖清单 | `pyproject.toml`、`uv.lock`、`requirements.txt` | 依赖声明与锁定 |
| 工程规范 | `.gitignore`、`.editorconfig`、`pyproject.toml` | 忽略规则与代码风格 |

### 1.2 绝对不要上传

| 类别 | 文件 | 原因 |
| --- | --- | --- |
| 真实配置 | `honeypot.ini`、`ai.local.ini`、`.env`、`scripts/honeypot.env` | 含管理端密码、AI Key、Webhook 地址 |
| 密钥文件 | `.secret_key`、`*.pem`、`*.key`、`deployment/*.json` | 会话密钥与令牌 |
| 运行数据 | `database/*.db`、`database/archive/`、`database/ai-archives/`、`dashboard/state/*.json`、`ssh_honeypot/state/` | 含真实攻击日志与诱饵凭证 |
| 日志 | `logs/`、`*.log` | 可能含 IP、载荷、密钥片段 |
| 环境 | `.venv/`、`venv/`、`__pycache__/`、`*.pyc` | 体积大且不可移植 |
| 编辑器 | `.vscode/`、`.idea/`、`.trae/`、`.history/` | 与本机绑定 |
| 临时文件 | 根目录零字节文件 `datetime` | 误生成，建议删除 |

以上均已在 `.gitignore` 中配置。**新增文件前先确认是否属于上表第二类。**

---

## 2. 为什么要这样排除

1. **安全**：蜜罐项目的配置文件天然包含「用于部署的密码」与『调用大模型的密钥』，一旦公开等于把系统交给攻击者。
2. **体积**：`.venv/` 与 `*.db` 常常超过百兆，会拖慢克隆并触发平台限制。
3. **可复现**：评审只需要「代码 + 模板 + 依赖清单」，真实配置可由模板一键生成。
4. **合规**：`logs/` 与 `database/` 中保存了攻击流量与诱饵凭证，属于敏感运行数据，不应公开传播。

## 3. 提交前自检（3 条命令）

```powershell
# 1) 确认暂存区没有真实配置与数据库
git status --short
git diff --cached --name-only | Select-String -Pattern 'honeypot\.ini$|ai\.local\.ini$|\.env$|\.db$|\.log$'

# 2) 扫描是否有 API Key / 密码字面量（应只命中 ai.local.ini.example 等模板或自检脚本）
Select-String -Path (git ls-files) -Pattern 'sk-[A-Za-z0-9]{20,}' -ErrorAction SilentlyContinue

# 3) 确认模板齐全
Test-Path honeypot.ini.example, ai.local.ini.example, .env.example, requirements.txt
```

第 2 条如命中 `ai.local.ini`、`honeypot.ini`，立即执行：

```powershell
git rm --cached honeypot.ini ai.local.ini
git commit -m "chore: 移除误提交的本地配置"
```

> 注意：`git rm --cached` 只把文件从版本库移除，本地文件仍在。**若密钥已经推送过，必须到平台侧更换密钥**，仅删除文件是不够的。

## 6. 与 AI 检测服务的关系

请求级检测服务（`xss_detector`，含 `src/`、`models/`、`requirements.txt`）是独立工程，有二选一做法：

1. **推荐**：单独建一个仓库，README 中写清「蜜罐主仓库」与「检测服务仓库」的关系与启动方式；
2. 或作为子目录 `detector/` 放入同一仓库（`models/attack_model.pkl` 约 19 MB，注意平台单文件 100 MB 限制）。

无论哪种，都需要在主仓库 README 的「AI 能力接入」一节写明检测服务的启动方式与端口（`127.0.0.1:8003`）。

## 7. 评审复现路径（写给评审看）

```powershell
git clone https://gitee.com/<你的账号>/honeypot-system.git
cd honeypot-system
uv sync
copy honeypot.ini.example honeypot.ini
copy ai.local.ini.example ai.local.ini
uv run python main.py
# 浏览器打开 http://127.0.0.1:5001/super/login（密码见 honeypot.ini 中 [admin]）
```

无密钥时 AI 功能自动降级为纯规则，不影响诱捕与展示；配置密钥后可执行
`uv run python scripts/ai_verify.py --full` 验证大模型链路。
