# 蜜迹2.4技术文档

## 项目概述

作品名称：蜜迹——证据驱动的智能蜜罐分析系统。团队：传智小分队。面向教学验证、竞赛展示与受控安全研究，采集多协议可疑行为并建立证据调查闭环。

## 需求分析

使用者需要同时处理不同协议、理解原始日志、核对AI解释、持续保存调查与人工意见。系统以“观察—研判—调查—复核”为工作主线，采用统一字段与五入口导航。

## 架构设计

接入层为Web/SSH/MySQL/Redis/FTP/Telnet；治理层管理连接、事件和告警；SQLite保存原始记录、分类结果与调查档案；investigation_core索引证据并控制范围；模型适配层支持本机Ollama、云端HTTPS和本机分类服务；管理端使用Flask与原生JS。

## AI技术方案与选型

分类模型负责请求级类别和概率，适合对接AI组的CPU服务；大模型负责有引用的解释、补查规划与故事线。分类与大模型采用不同的调用路径与审计记录。

本机模式适合数据在本机处理的场景，沿用Ollama模型选择、下载、验收。云端模式适合本机资源有限的设备，通过HTTPS与OpenAI兼容协议接入；使用者显式确认数据发送和费用。模型名、服务地址与密钥由部署者配置，程序不绑定自研基础模型身份。

优化策略包括代表证据选择、最多3次补查/60候选/12代表证据/90秒总预算、并发额度、结构化输出校验、分类异步队列、超时与故障恢复。规则、模型与人工意见分别保存。

## 核心功能实现

多协议处理器返回受控数据，关闭MySQL客户端文件索取及FTP主动数据连接，限制输入与会话资源。证据通过来源、记录ID和时间定位；协议筛选贯穿事件、会话与调查。风险目标保存IP、等级、状态、标签、备注与版本号，操作不改变系统防火墙。

调查保存建案快照与范围。模型补查只能在授权范围中查询已有记录；故事线区分程序事实与模型推测。引用可打开原文，反馈与处理状态独立保存，调查以JSON导出。

## 技术创新点

1. 将多协议诱捕与证据调查连接，协议记录进入统一的筛选、会话和建案流程。
2. 规则、分类、大模型、人工四类判断留存来源，建议融合分不覆盖规则。
3. 受限主动补查与带引用故事线，形成可复核的模型解释。
4. 本机/云端可选模型与CPU分类接口，兼顾不同设备的运行需求。

## 应用创新点

从收集日志延伸到来源关注、过程关联、证据核对和调查交接；五入口工作区保持统一上下文，降低在多个独立页面间寻找信息的成本。保留缓存地图和可访问的页内标签交互。

## 测试与部署

软件回归、真实本机协议连接、分类接口隔离联调、浏览器流程与独立目录启动分项记录。依赖通过requirements-lock.txt固定；首次启动配置管理员密码，默认仅本机监听。详细结果见测试与验证说明及validation。

## 总结与展望

蜜迹形成了六协议采集、规则研判、模型增强、原文引用、人工复核与调查导出的完整流程。后续可在统一字段接口上扩展模型类别与应用场景，持续使用独立标注集评价模型效果。
