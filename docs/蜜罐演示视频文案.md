## 二、叙事结构

整条片子不按“功能菜单”平铺，而按一次攻击的生命周期推进：

```text
布饵（启动）
  → 被看见（Web / SSH / 多协议）
  → 被归一（统一事件模型）
  → 被看见（态势大屏）
  → 被研判（规则 + AI 双链路）
  → 被复核（证据与调查）
  → 边界（授权、降级、不接触真实业务）
```

旁白只回答三个问题：

- 攻击者看到了什么？
- 防守方记录了什么？
- 这些记录如何变成可复核的结论？

### 镜头 03｜00:55–01:35｜Web：看起来像官网，实际上是记录点

**画面**

- `01_web_home.png`：正常搜索 `python tutorial`，结果页正常返回。
- 搜索框输入 `<script>alert("honeypot-demo")</script>`，页面把尖括号转义后原样显示。
- 地址栏输入 `/products?id=1 UNION SELECT username,password FROM users`，页面仍然是普通产品页。
- 地址栏输入 `/download?file=../../etc/passwd`，返回 404。
- 切 `02_web_admin_login.png`：`/admin` 诱饵后台，输入一组演示账号，登录失败。
- 切 `04_dashboard.png` 右侧实时日志：`AI XSS +25`、`AI SENSITIVE PATH +25` 等标签滑入。

**旁白**

> 先看 Web。首页看起来像一家普通企业站：新闻、产品、解决方案。但搜索框、产品参数、下载路径，都是记录点。输入一段脚本、一个联合查询、一段路径遍历，页面可能仍然返回 200，也可能只给一个 404。对访问者来说，什么都没发生；对防守方来说，请求方法、路径、参数、UA 和响应状态，已经写进原始请求表。旁边这个更像真的：/admin 是一套诱饵后台。它不连接真实业务，也没有读取本机文件。

**屏幕字**

- `200` / `404` 状态标签依次出现
- 页面正常 ≠ 没有记录
- `/admin` 是诱饵后台，不是管理端

**剪辑**

- 输入攻击载荷时，键盘声可适当放大；页面返回时音乐留白半秒。
- 实时日志标签用 0.3 秒高亮框标出，不要遮挡日志正文。

### 镜头 04｜01:35–02:20｜SSH 与多协议：把交互做深

**画面**

- 终端：`ssh root@127.0.0.1 -p 2222`，密码输入过程完全遮罩。
- 依次执行并展示：
  - `whoami` → `root`
  - `uname -a` → `Linux data-node-436c ... Ubuntu`
  - `cat /etc/passwd` → 仿真账户列表
  - `sysinfo` → 主机人设、系统、角色、工作目录
  - `appctl status` → `postgresql: running`、`redis: running`、`backup-worker: stopped`
  - `demo_unknown_cmd` → `command not found`
- 四分屏展示多协议输出：
  - MySQL：`8.0.36`
  - Redis：`redis_version:6.2.6` 与诱饵键值
  - FTP：`virtual_login_accepted`
  - Telnet：`D-Link DI-8003` 横幅与 BusyBox shell

**旁白**

> SSH 蜜罐把交互做得更深。登录后，whoami、uname、cat /etc/passwd、ls、ip addr，都有仿真输出；sysinfo 和 appctl 还准备了主机人设与服务状态。未知命令不会执行，只会被安全地回一句 command not found。同一套事件模型也接住了数据库、文件和远程管理协议：MySQL 假握手、Redis 假键值、FTP 匿名登录、Telnet 的 D-Link 路由器横幅。它们共同构成一张低成本的诱捕网。

**屏幕字**

- 虚拟登录成功 ≠ 真实主机失陷
- 所有命令均在仿真文件系统中完成
- 六个协议，一套事件模型

**剪辑**

- SSH 命令输出可 1.5 倍速，但 `command not found` 保留正常速度。
- 四分屏每个协议停留 2.5–3 秒，配一个协议图标与一句结果标签。

**画面**

**屏幕字**

- 数据卡：`135` 事件 / `6` 类来源 / `39` 可疑请求 / `67` 最高分 / `9` 会话 / `7` 攻击源
- 小字：画面为运行中截屏，数据卡为整场汇总
- 地图角标：演示流量来自 127.0.0.1，非真实公网地理分布

**剪辑**

- 这是全片的信息高峰，旁白放慢，数字逐个跳出，不要一次性铺满。
- 大屏原图上的“总攻击 73”等数字是截屏时刻的值，不要用特写强调；以数据卡为准。

### 镜头 06｜03:05–04:00｜研判：两条 AI 链路，各自保留证据

**画面**

- `07_ai_analysis.png` 局部：自动攻击分析报告卡片，标题与证据引用逐行高亮。
- `08_ai_detection.png` 局部：规则判断与 AI 判断并排；高亮“规则 22 / AI +25”“规则 25 / AI +25”。
- `09_ai_interactions.png` 局部：SSH 未知命令、`sysinfo`、`appctl status` 的“输入 → 回应”。
- 数据卡浮出：`39` 条 AI 对照 / `28` 条规则+AI / `11` 条纯规则；`81/81` 报告完成；`110` 次调用、`108` 次成功。

**旁白**

> 接下来是两条独立的 AI 链路。第一条在请求级：规则先打分，模型再做一次分类，给出 AI 加分。两条证据链都保留，规则分不会被覆盖。这次有 39 条事件进入 AI 对照，28 条是规则加 AI，11 条仍是纯规则。XSS 是 22 加 25，SQL 注入是 25 加 25。现在，模型判 normal 时生效加分是 0，但来源仍然记录为规则加 AI，表示它确实看过；历史事件仍保留当时的分值。第二条链路是大模型分析：81 份报告全部完成，110 次调用成功 108 次。它把零散日志整理成攻击过程，也把“不能确认”写进结论。

**屏幕字**

- 规则 + AI：分数相加，结论并存
- normal 也参与，但生效加分是 0
- 81/81 报告完成
- 小字：17 条对照因单 IP 每小时额度未进入分析，属设计内限流；历史事件保留旧分值

**剪辑**

- 说到“规则分不会被覆盖”时，给规则分一个锁定图标；说到“normal 加 0”时，数字从 9 跳到 0，再出现 `final_source=rule+ai`。
- 不要展示模型原始回复中的大段 JSON；只保留标题、风险级别、证据引用。

### 镜头 07｜04:00–04:35｜复核：AI 是助手，不是裁判

**画面**

- 放大 `07_ai_analysis.png` 中的报告正文：
  - “sqlmap 探测 /admin，疑似 SQL 注入侦察”
  - “参数为空，未观察到注入载荷或成功响应”
  - “更符合自动化漏洞扫描与信息收集”
- 实拍：在报告上点击“加入调查工作台”，建立一条调查；展示关联证据、人工笔记、状态与导出入口。
- 若没有现成调查数据，不要拍空列表；改用报告详情页 + 侧边栏“调查工作台”入口做概念说明。

**旁白**

> 这份报告就是一个例子。模型看到的是 sqlmap 访问 /admin，它没有直接说“已被攻破”，而是写：参数为空，未观察到注入载荷或成功响应，更符合自动化扫描与信息收集。关键判断都带原文引用，可以回到原始请求。报告可以加入调查工作台，和同源事件放在一起；人工补充笔记、改状态、导出，AI 的结论和人的结论分开保存。这样，AI 是助手，不是裁判。

**屏幕字**

- “未观察到注入载荷或成功响应”
- “更符合自动化扫描与信息收集”
- AI 结论 ≠ 攻击成功
- 证据可回跳原始日志

**剪辑**

- 引用文字用“引号 + 淡黄底”标出，不要做成大字报。
- “AI 是助手，不是裁判”落字时，画面回到大屏，音乐收束。

这份报告就是一个例子。模型看到的是 sqlmap 访问 /admin，它没有直接说“已被攻破”，而是写：参数为空，未观察到注入载荷或成功响应，更符合自动化扫描与信息收集。关键判断都带原文引用，可以回到原始请求。报告可以加入调查工作台，和同源事件放在一起；人工补充笔记、改状态、导出，AI 的结论和人的结论分开保存。这样，AI 是助手，不是裁判。[停顿]

它的价值，不是抓住每一个攻击者，而是让每一次探测都留下证据；不是替代真实防护，而是给防守方争取时间。系统只用于授权环境，默认不接触真实业务；诱饵预览不会访问目标地址，AI 不可用时自动降级。蜜罐不是万能盾，但它能让下一次探测，变成下一次暴露。[停顿]

把攻击留在诱饵里，把证据带到屏幕上。这，就是这套蜜罐系统想做的事。

## 六、录制执行清单

### 6.1 录制前

- [ ] 使用干净的演示数据库，避免把历史真实数据录进画面。
- [ ] 确认 `honeypot.ini` 中无真实密码、Webhook、API Key；录屏前关闭无关通知。
- [ ] 浏览器只保留必要标签页：Web 首页、`/admin`、Dashboard 登录、大屏、AI 分析、AI 对照、交互回放。
- [ ] 分辨率 1920×1080，浏览器缩放 110%；隐藏书签栏；终端字号不小于 16 px。
- [ ] 准备两套素材：实拍屏幕录制 + `docs/screenshots/` 中的静态图，用于插入特写和补帧。

### 6.2 建议命令

```powershell
# 1) 启动主控（会同时拉起默认蜜罐与管理端）
uv run python main.py

# 2) 生成 Web / ERP / 受控交互流量（22 步）
uv run python scripts/mixed_attack_demo.py --business --gap 1 --timeout 15 --output docs/test-run

# 3) 生成多协议流量（密码取自启动窗口的诱饵密码）
uv run python scripts/demo/protocol_traffic.py --ssh-password <启动窗口密码> --json docs/test-run/protocol.json

# 4) 追加 Telnet 演示
uv run python scripts/demo/protocol_traffic.py --only telnet --telnet-user root --telnet-password <诱饵密码> --json docs/test-run/telnet.json
```

> 以上脚本只向 `127.0.0.1` 发送合成请求，不扫描网段、不爆破真实目标。录制时不要把 `<启动窗口密码>` 留在画面上。

### 6.3 录制顺序

1. 先录启动与端口汇总，再录大屏空镜，最后录攻击流量，方便剪辑时做“从静到动”的对比。
2. Web 攻击载荷逐条输入，每条之间停 1 秒，给后期留剪切点。
3. SSH 命令逐条执行，`command not found` 单独录一条特写。
4. 多协议输出用分屏录制，每个协议保留 3 秒完整输出。
5. AI 页面先等报告生成完成，再录；不要录“加载中”超过 2 秒。
6. 调查工作台若没有现成案例，先手动建立一条演示调查，避免拍到空列表。

### 6.4 后期

- 等待时间超过 3 秒的段落做 2–4 倍速，保留进度条或光标运动，避免“跳帧感”。
- 所有关键数字加数据卡，不依赖观众暂停阅读日志。
- 大屏截图上的数字与数据卡不一致时，加小字“画面为运行中截屏，数据卡为整场汇总”。
- 不伪造 AI 回复、不拼接不存在的攻击成功画面；AI 的“不能确认”本身就是展示点。
- 片尾加免责声明，至少停留 2 秒。
