一、 项目代码结构全景图与含义解析
根据你的论文和代码，系统可以分为四个层次：配置与启动层、核心功能层、数据持久层、文档与依赖层。

1. 配置与启动层（系统总控）
main.py（总控大脑）：你刚才截图报错的那个文件。它是整个系统的“总指挥”。负责检查端口占用、拉起三个子服务（SSH、Web、Dashboard）、实时监控它们的日志、捕获动态生成的诱饵密码、并在某个服务意外崩溃时自动重启。论文中提到的“统一启动入口”就是它。

app_config.py（配置管家）：负责读取配置文件。它规定了配置读取的优先级：环境变量 > honeypot.ini > 代码默认值。它管理着数据库类型（SQLite/MySQL）、SSH/Web/Dashboard 的端口、管理员密码、告警阈值等所有参数。

env_utils.py（工具助手）：app_config.py 的辅助模块，封装了读取环境变量的工具函数（如 env_bool、env_int），让配置读取更规范、少写重复代码。

honeypot.ini.example（配置模板）：系统配置的样板。项目首次启动时，run.bat 会自动把它复制成 honeypot.ini，你需要在这个真实的 ini 文件里配置你的端口、密码、企业微信 Webhook 等。

2. 核心功能层（三大服务）
根据 main.py 中的 SERVICES 列表，这三个模块是独立运行的子进程：

ssh_honeypot/server.py（SSH 仿真端）：对应论文 5.2 节。基于 Paramiko 库接管 SSH 认证和通道。它负责监听 2222 端口，记录攻击者的用户名、密码、来源 IP，并提供一个内存级的虚拟文件系统，模拟 Ubuntu 终端（如你截图里看到的 root@ubuntu-server）。它把认证失败、成功、命令审计等事件写入统一事件模型。

web_honeypot/server.py（Web 诱捕端）：对应论文 5.3 节。基于 Flask 框架监听 5000 端口。它模拟企业官网、诱饵后台（/admin）、敏感文件路径（如 /.env、/.git/config）。它内置了 SQL 注入、XSS 等规则，采用“多特征加权 + 双阈值分层”机制进行风险评分（20分可疑，40分高危）。

dashboard/server.py（管理端/大屏）：对应论文 5.5 节。同样基于 Flask 监听 5001 端口。它是真实的态势感知大屏，提供 JSON API（见 API.md）。它从数据库读取统一事件模型的数据，通过 ECharts 展示统计、地理分布、可疑请求和攻击链。

3. 数据与工具层（支撑模块，代码中未直接给出但逻辑存在）
db/（数据访问层）：负责数据库连接、事件写入、统计聚合和归档。实现了论文 4.4 节的“统一事件日志表 (event_log)”、“原始请求表 (raw_requests)”、“会话追踪表”和“地理缓存表”。

utils/（工具库）：包含日志设置 (logger.py)、IP 地理定位、HTTP 指纹识别、告警发送等通用功能。

4. 文档与依赖层
README.md：项目整体说明，教你如何部署和启动。

API.md：详细的接口文档，列出了 Dashboard、Web 蜜罐的所有 HTTP 接口，是答辩演示和二次开发的指南。

pyproject.toml 和 uv.lock：Python 依赖声明和版本锁定文件。保证在任何电脑上 uv sync 都能装出一模一样的运行环境。














展示启动：双击 scripts\run.bat，让老师看到系统“一键拉起三个服务”的过程，说明你的系统架构是高度集成的（体现 main.py 的价值）。

演示 SSH 诱捕：新开 PowerShell，输入 ssh root@127.0.0.1 -p 2222，输入密码 toor。进入终端后敲几个命令（如 ls、cat /etc/passwd），向老师说明这是中交互蜜罐，全程不触达宿主机真实文件。

演示 Web 诱捕：浏览器访问 http://127.0.0.1:5000，点击几个页面。然后访问 http://127.0.0.1:5000/admin 尝试用诱饵密码登录。

展示大屏与统一事件模型：打开 http://127.0.0.1:5001/dashboard，用 admin / Admin@2024! 登录。指着大屏说：“老师，刚才的 SSH 命令和 Web 探测行为，已经被统一事件模型汇聚在这里了。我们可以通过来源 IP 和会话标识进行跨协议联查和攻击链追踪。”

结束系统：回到黑窗口，按 Ctrl + C，说明系统支持优雅停机。










ssh_honeypot/vfs.py —— 虚拟文件系统
用途：在内存里伪造一整台 Linux 的文件系统，攻击者 ls/cat/mkdir/rm 都操作这套内存结构，真实主机毫发无损。

VIRTUAL_FS：目录树（/etc /var /root /home /tmp /proc ...）。
VIRTUAL_FILES：假文件内容字典，关键诱饵：
/root/secret.txt：伪造的内网凭证/数据库连接串（引诱攻击者拿去横向移动，便于追踪）；
/etc/passwd、/etc/shadow（假哈希）、/etc/os-release、/var/log/auth.log；
~/.bash_history（伪造管理员历史命令）、~/.ssh/id_rsa（假私钥）。
GLOBAL_FS_STATE / GLOBAL_FILES_CONTENT：目录结构和文件内容的全局可变副本——攻击者 mkdir/echo 写文件/rm 都改这里，并且对同一IP的重连可见（会话持久化的基础）。
